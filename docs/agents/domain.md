# Domain Docs

## Layout

Single-context:
- `CONTEXT.md` at the repository root.
- Architecture decisions in `docs/adr/`.

## Consumer rules

Before exploring code, read CONTEXT.md and the ADRs relevant to the task.

If these documents do not exist, proceed silently. Domain modeling creates
them when terminology or decisions are resolved.

Use the glossary's terminology in specs, tickets, code and tests.
Flag contradictions with existing ADRs before proposing a different decision.
